# Fix: "Error 400: redirect_uri_mismatch" – Google Sign-In

If users see **"Access blocked: This app's request is invalid"** with **Error 400: redirect_uri_mismatch** when signing in with Google, the redirect URI your app sends is not listed in your Google Cloud OAuth client.

**Important:** Google **Web application** OAuth clients do **not** accept custom URL schemes like `grabdocs://`. They only allow **http** or **https** URLs with a valid domain (e.g. `.com`). So we use a **backend HTTPS callback**; the backend exchanges the code and redirects the user back to the app via a deep link.

## What to do (Google Cloud Console)

1. Open [Google Cloud Console](https://console.cloud.google.com) and select your project (or the one used by GrabDocs).
2. Go to **APIs & Services** → **Credentials**.
3. Open the **OAuth 2.0 Client ID** that the mobile app uses (the same “Web application” client you use for GrabDocs).
4. Under **Authorized redirect URIs**, click **+ ADD URI** and add **exactly** (no trailing slash):

   ```
   https://api.grabdocs.com/api/v1/web/auth/callback
   ```

5. Click **Save**.

After saving, wait a minute and try Google sign-in again.

## Redirect URIs used by the app

| Environment        | Redirect URI                                              | Where to add it                          |
|--------------------|-----------------------------------------------------------|------------------------------------------|
| Production (APK/IPA) | `https://api.grabdocs.com/api/v1/web/auth/callback`    | Same OAuth “Web application” client      |
| Development (Expo) | Expo proxy URL (e.g. `https://auth.expo.io/@…/grabdocs`) | Same or a separate “Web” OAuth client     |

The production app uses the **HTTPS backend callback** so Google accepts it. The backend receives the code, exchanges it, and redirects the user to `grabdocs://login-success?token=...` so the app opens and completes login.

## Why not `grabdocs://auth/callback`?

Google’s **Web application** client type only allows redirect URIs that:

- Use `http` or `https`
- End with a public top-level domain (e.g. `.com`, `.org`)
- Use a valid top private domain

Custom schemes like `grabdocs://auth/callback` are rejected with “Invalid Redirect: must end with a public top-level domain” and “must use a domain that is a valid top private domain.” So we use the backend URL above instead.

## Optional: development / Expo Go

If you also sign in from **Expo Go** or a dev build, the redirect URI is generated by Expo (e.g. `exp://…` or Expo proxy). Either:

- Add that exact URI to your OAuth client (you can log it in the app: “Google Auth initialized with redirect URI: …”), or  
- Use a separate OAuth “Web application” client for development and set `EXPO_PUBLIC_GOOGLE_CLIENT_ID_WEB` (and add the Expo redirect URI to that client).

## Checklist

- [ ] Added `https://api.grabdocs.com/api/v1/web/auth/callback` to **Authorized redirect URIs** for the OAuth client used by the production app.
- [ ] No typo (e.g. `http://` instead of `https://`, or wrong path).
- [ ] Saved the credentials and waited a minute before testing again.

If it still fails, double-check that the client ID in your app (e.g. EAS env or `.env`) matches the client in Console where you added the redirect URI.
